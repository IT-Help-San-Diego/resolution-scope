## 2. End-to-end build path PROVEN

The Microkit "hello" example built and booted:

```
aarch64-none-elf-gcc -c -nostdlib -ffreestanding ... hello.c -o hello.o
aarch64-none-elf-ld ... hello.o -lmicrokit -Tmicrokit.ld -o hello.elf
bin/microkit hello.system ... -o loader.img
  MICROKIT|CAPDL SPEC: number of root objects = 34, spec footprint = 4.92 KiB
  MICROKIT|LOADER: image file size = 2.62 MiB
```

This confirms the FULL contract for our compartment: `.system` XML →
`aarch64-none-elf-gcc` component ELF → `bin/microkit` tool → capDL generated
internally → bootable `loader.img`. The hand-written `.cdl` is confirmed
obsolete (capDL is generated by the microkit tool, not authored).

## 3. QEMU runtime finding (the one remaining gap)

Booting `loader.img` under QEMU reaches "Bootstrapping kernel" then faults:

```
Warning: Could not infer GIC interrupt target ID, assuming 0.
KERNEL DATA ABORT!
Faulting instruction: 0x8060029100
FAR: 0x80bf800000 ESR (DFSR): 0x96000050
halting...
```

**Diagnosis so far (measured, not resolved):**
- The SDK board is built for **GICv2** (`CONFIG_ARM_GIC_V3_SUPPORT` disabled).
- The fault is at `FAR: 0x80bf800000` (GIC distributor region) during kernel
  bootstrap, after the "Could not infer GIC interrupt target ID" warning.
- Tried: `gic-version=2` (no change), canonical seL4 command from
  `src/plat/qemu-arm-virt/config.cmake` (`-machine virt,secure=off,
  virtualization=on,gic-version=2 -cpu cortex-a53 -m 1024`, no `highmem=off`
  for aarch64 — my earlier `highmem=off` was wrong for 64-bit) — still aborts.

This is the known **seL4 GICv2 driver vs. newer-QEMU virt GIC device-tree**
class (seL4's config.cmake pins a minimum QEMU 3.1; the box has 8.2.2). The
fix is a QEMU version pin or a GIC DT overlay, not a code change. Recorded here
with the exact signature so the next session starts from the fault, not from
scratch.
